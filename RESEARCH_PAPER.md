### **Abstract**
*Ransomware continues to represent a catastrophic cyber threat to enterprise and individual computing infrastructure by encrypting sensitive user files and demanding extortion payments. Traditional antivirus and endpoint detection mechanisms rely heavily on static binary signatures, file hashes, and pre-compiled heuristic rules—defenses that are routinely bypassed by polymorphic engines, packers, and memory-injected payloads. This paper presents a real-time behavioral ransomware detection framework that inspects the dynamic sequence of system calls (`syscalls`) generated by executing processes. The system normalizes OS-specific API variants into a canonical 18-token representation and extracts a 35-dimensional behavioral feature vector capturing unigram distributions, temporal transition bigrams, write-to-read ratios, Shannon entropy, write burst lengths, and cyclic file-replacement patterns (`write` $\to$ `rename` $\to$ `unlink`).*

*To achieve pre-encryption containment, an overlapping sliding window mechanism ($W = 36$, $S = 12$) processes partial syscall streams, enabling early interdiction before bulk file destruction occurs. A hierarchical four-model machine learning ensemble—incorporating Gradient Boosted Decision Trees (GBDT) for fast window screening, coupled with Random Forest, Calibrated Linear Support Vector Machines (SVM), and a Multilayer Perceptron (MLP) for consensus confirmation—delivers robust classification. Experimental evaluation across 1,570 synthetic and replayed execution traces achieves an overall ensemble accuracy of 97.27%, an F1-score of 97.10%, and a low false-positive rate of 1.77% on complex benign workloads. The system successfully detects a zero-day held-out ransomware family (`writev-swap`) with 94.38% recall at an average inference latency under 1.8 ms per window. The proposed framework is realized in an end-to-end web-based threat analysis console that demonstrates real-time interdiction, model explainability, and persistent cross-device audit logging.*

**Index Terms—** *Ransomware Detection, Behavioral Analysis, System Call Sequences, Sliding Window, Machine Learning Ensemble, Early Interdiction, Endpoint Security, Explainable AI.*

## I. INTRODUCTION

Ransomware attacks have evolved into a sophisticated, multi-billion-dollar extortion ecosystem. Unlike conventional malware designed for covert reconnaissance or resource hijacking, ransomware executes rapid, destructive bulk file encryption. Once a host system is compromised, ransomware traverses directory trees, enumerates sensitive file types (documents, databases, source code, images), reads original content into memory, writes encrypted ciphertext, and deletes or overwrites the original unencrypted files. 

```
+-------------------------------------------------------------------------+
|                         STATIC DETECTION (TRADITIONAL)                  |
|  Executable File  ───►  MD5/SHA256 Hash Match  ───►  Signature Database |
|  [Vulnerable to: Polymorphism, Runtime Packing, Zero-Day Payloads]      |
+-------------------------------------------------------------------------+
                                    VS
+-------------------------------------------------------------------------+
|                       BEHAVIORAL DETECTION (PROPOSED)                   |
|  Running Process  ───►  Syscall Interception  ───►  Dynamic Window      |
|                   ───►  35-D Feature Vector   ───►  4-Model AI Ensemble |
|  [Outcome: Real-Time Early Interdiction & Automatic Process Termination]|
+-------------------------------------------------------------------------+
```

### A. Problem Statement
The fundamental limitation of static defenses lies in their reliance on known file attributes. Adversaries easily bypass hash lookups using simple recompilation, dynamic API resolution, or crypters. While the binary structure can mutate infinitely, the *runtime behavioral requirements* of a file locker remain invariant: any ransomware must interact with the operating system kernel via system calls to open, read, write, rename, and delete files. 

The primary challenge is designing a detector capable of:
1. Differentiating legitimate high-throughput file modifications (e.g., text editors saving backups, software compilers, archive extractors) from malicious cryptographic loops.
2. Detecting encryption behavior **early in the execution timeline** ($k < 35$ operations) to prevent data loss.
3. Maintaining sub-2 ms inference latency suitable for online endpoint deployment.

### B. Objectives and Key Contributions
The principal contributions of this research are:
- **Universal System Call Normalization:** A lightweight mapping engine that converts disparate OS-level system calls into a normalized 18-token alphabet $\mathcal{V}$, eliminating runtime noise and architecture dependencies.
- **35-Dimensional Behavioral Feature Formulation:** Mathematical modeling of sequential bigram transitions, write-to-read ratios, write burst lengths, and cyclic file replacement frequencies.
- **Sliding-Window Early Interdiction:** An overlapping window pipeline ($W=36, S=12$) that flags malicious loop anomalies during early calls, halting process execution before full trace completion.
- **Hierarchical Multi-Model AI Ensemble:** A two-tier screening and consensus architecture combining GBDT, Random Forest, Calibrated Linear SVM, and a dual-layer MLP that outperforms single-classifier baselines.
- **Complete Full-Stack Implementation:** A deployed, interactive web-based analysis platform featuring real-time consensus telemetry, stream visualization, and cross-system persistent audit tracking.

## II. LITERATURE REVIEW & COMPARATIVE ANALYSIS

Numerous runtime detection systems have been explored in academic and industrial literature:

- **UNVEIL [1]:** Monitors system I/O events and screen buffer alterations in a sandbox. While effective at identifying desktop lockers and massive file writes, its heavy sandboxing introduces substantial latency, making real-time endpoint deployment impractical.
- **ShieldFS [2]:** Introduces a ransomware-aware virtual file system driver that monitors file activity and creates shadow copies for recovery. However, kernel filesystem driver installation involves high operational overhead and kernel panic risks.
- **Automated Dynamic Analysis (Sgandurra et al.) [3]:** Employs dynamic behavioral feature synthesis across API invocations, but evaluates entire execution traces post-mortem, failing to provide early interdiction.
- **Syscall ML Classifiers (Bae et al.) [4]:** Explored n-gram system call analysis using standard classifiers, but relied on full-length traces without dynamic windowing or consensus ensembles.
- **Honeypot Decoy Techniques (Moore) [5]:** Deploys hidden decoy directories to trap ransomware. Attackers frequently evade decoys by sorting directories alphabetically or encrypting prioritized user profiles first.

### Comparative Summary Against Published Works

| Research System | Detection Mechanism | Feature Space | Early Interdiction | False Alarm Mitigation | Reported Accuracy |
| :--- | :--- | :--- | :---: | :---: | :---: |
| **UNVEIL (Kharraz et al., 2016) [1]** | I/O pattern & screen buffer diffs | High-level I/O metrics | $\times$ (Post-trace) | Moderate | 96.3% |
| **ShieldFS (Continella et al., 2016) [2]** | Custom file-system driver + shadow copy | Low-level FS operations | $\checkmark$ (Mid-run) | High (Shadow recovery) | 97.0% |
| **Dynamic Analysis (Sgandurra, 2018) [3]** | Dynamic API & Registry inspection | Multi-domain features | $\times$ (Post-trace) | Moderate | 96.5% |

## IV. BEHAVIORAL FEATURE ENGINEERING

To extract domain-specific signals from raw system-call windows without incurring prohibitive computational cost, the engine computes a 35-dimensional feature vector $\mathbf{x} \in \mathbb{R}^{35}$:

### A. Syscall Relative Frequencies (15 Features)
Measures the occurrence rate of essential file and process management primitives over window $W = (c_1, \dots, c_N)$:

$$x_k = \frac{\sum_{t=1}^N \mathbb{I}(c_t = s_k)}{N}, \quad s_k \in \mathcal{V}_{\text{core}}$$

where $\mathcal{V}_{\text{core}} = \{\text{open}, \text{read}, \text{write}, \text{close}, \text{stat}, \text{getdents}, \text{rename}, \text{unlink}, \text{fsync}, \text{pwrite}, \text{writev}, \text{link}, \text{execve}, \text{lseek}, \text{mmap}\}$.

### B. Sequential Bigram Transition Rates (14 Features)
Ransomware file encryption follows strict procedural orderings (e.g., directory enumeration followed by opening a file, reading plaintext, writing ciphertext, renaming with a lock extension, and unlinking the original). Bigram features capture adjacent transitions:

$$x_{(u \to v)} = \frac{\sum_{t=1}^{N-1} \mathbb{I}(c_t = u \land c_{t+1} = v)}{N - 1}$$

Target transitions include: $\text{open} \to \text{read}$, $\text{read} \to \text{write}$, $\text{write} \to \text{close}$, $\text{write} \to \text{rename}$, $\text{rename} \to \text{unlink}$, $\text{getdents} \to \text{open}$, $\text{stat} \to \text{open}$, $\text{read} \to \text{close}$, $\text{close} \to \text{unlink}$, $\text{write} \to \text{write}$, $\text{read} \to \text{read}$, $\text{open} \to \text{write}$, $\text{unlink} \to \text{open}$, and $\text{close} \to \text{open}$.

### C. Write-to-Read Ratio ($\rho_{\text{wr}}$)
Benign processes (such as compilers or editors) frequently exhibit balanced read/write ratios or high read volumes. Ransomware exhibits continuous, elevated write volumes:

$$\rho_{\text{wr}} = \frac{\text{Count}(\text{write-family}) + \epsilon}{\text{Count}(\text{read-family}) + 1.0}$$

### D. Destructive Replacement Cycle Rate ($\Lambda$)
Quantifies the occurrence of the canonical locker destruction pattern ($\text{write} \to \text{rename} \to \text{unlink}$) within a single temporal window:

$$\Lambda = \frac{\text{Count}(\text{write}) \times \left[\text{Count}(\text{rename}) + \text{Count}(\text{unlink})\right]}{N^2}$$

### E. Normalized Shannon Syscall Entropy ($H$)
Captures the degree of operational diversity. Monotonous encryption loops display constrained entropy compared to multi-threaded enterprise software:

$$H = -\frac{\sum_{k=1}^{|\mathcal{V}|} p(k) \ln(p(k) + \epsilon)}{\ln(|\mathcal{V}| + 1)}$$

### F. Maximum Write Burst Length ($R_{\text{write}}$)
Computes the length of the longest unbroken sequence of consecutive write-family calls normalized by window size $N$:

$$R_{\text{write}} = \frac{\max \left\{ \text{consecutive run of write calls} \right\}}{N}$$

## V. MACHINE LEARNING ENSEMBLE & DECISION LOGIC

The multi-model ensemble combines four diverse statistical and neural learning paradigms:

1. **Gradient Boosted Decision Trees (GBDT):** Serves as the primary stage-one screener ($M = 80$ estimators, learning rate $\eta = 0.08$, max depth $d = 3$). GBDT rapidly detects non-linear decision boundaries.
2. **Random Forest (RF):** Comprises 100 decorrelated decision trees using bootstrap aggregation with Gini impurity splitting to minimize variance on unseen noise.
3. **Calibrated Linear Support Vector Machine (Linear SVM):** Constructs an optimal hyper-plane with $L_2$ regularization. Platt scaling (via `CalibratedClassifierCV`) transforms raw distance metrics into well-calibrated posterior probabilities.
4. **Multilayer Perceptron (MLP):** A fully-connected neural network with hidden layers $(64, 32)$, ReLU activation, and Adam optimization ($\alpha = 0.0001$) to capture complex high-order cross-feature correlations.

### A. Ensemble Decision Formulation
Let $P_{\text{GB}}(\mathbf{x})$, $P_{\text{RF}}(\mathbf{x})$, $P_{\text{SVM}}(\mathbf{x})$, and $P_{\text{MLP}}(\mathbf{x})$ denote the posterior malicious probabilities produced by each model. The consensus confirmation score $O(\mathbf{x})$ is defined as:

$$O(\mathbf{x}) = \frac{P_{\text{RF}}(\mathbf{x}) + P_{\text{SVM}}(\mathbf{x}) + P_{\text{MLP}}(\mathbf{x})}{3}$$

The final threat score $\mathcal{S}(\mathbf{x})$ is computed using a tiered damping function parameterized by screening floor $\theta_{\text{floor}} = 0.30$:

$$\mathcal{S}(\mathbf{x}) = \begin{cases} 
\min\left(0.20 \cdot P_{\text{GB}}(\mathbf{x}) + 0.35 \cdot O(\mathbf{x}), \; 0.34 \cdot P_{\text{GB}}(\mathbf{x}) + 0.66 \cdot O(\mathbf{x})\right), & \text{if } P_{\text{GB}}(\mathbf{x}) < 0.30 \\ 
0.34 \cdot P_{\text{GB}}(\mathbf{x}) + 0.66 \cdot O(\mathbf{x}), & \text{if } P_{\text{GB}}(\mathbf{x}) \ge 0.30 
\end{cases}$$

An alert and process termination signal is triggered whenever $\mathcal{S}(\mathbf{x}) \ge \theta_{\text{alert}} = 0.55$.

## IX. LIMITATIONS & FUTURE SCOPE

1. **In-Memory & Network-Only Attacks:** Ransomware variants operating strictly in-memory without touching local storage require complementary network flow monitoring.
2. **Kernel Hook Hardening:** Future extensions will integrate eBPF and Windows Kernel-Mode drivers to prevent user-space tracing evasion.
3. **Automated Key Recovery:** Exploring volatile memory checkpointing during early interdiction to extract encryption keys prior to process termination.

---

## X. CONCLUSION

This paper presented an effective behavioral ransomware detection and early interdiction framework based on dynamic system call sequence analysis. By converting low-level kernel invocations into a canonical vocabulary, extracting 35 temporal and cyclic file-replacement features, and applying an overlapping sliding-window ensemble (GBDT, RF, Calibrated SVM, and MLP), the system achieves 97.27% classification accuracy with a 1.77% false positive rate. The framework successfully interdicts active ransomware in its initial phases, preserving over 93% of user files, while maintaining a 94.38% zero-day detection rate on completely unseen attack families.
